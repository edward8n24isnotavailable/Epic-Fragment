# Epic Fragment 当前流程的美术制作规格

版本：2026-09-30。依据：`data/game_data.json`、`scripts/world.gd`、当前角色碰撞和已验证的 Blender 烘焙房。

## 1. 当前缺什么

现阶段需要的是 **完整的分层环境、可动角色及武器动画、独立交互道具和战斗反馈**。现有两张像素角色立像、少量 64×64 纹理和 256×256 道具只够占位；新验证房只覆盖一个独立房间，不是正式地图的美术。

| 类别 | 当前状态 | 制作目标 |
| --- | --- | --- |
| 主角 | 无名囚徒 1 张立像；五出身共用 | 囚徒基础人体 + 五种装备外观；移动、跳跃、攻击、防御、受击、死亡动画 |
| 敌人 | 10 个遭遇共用灰烬士兵图 | 7 种可辨识外观：疯兵、灰烬士兵、狱卒、腐化骑士、责难官、典狱长、禁卫队长；狱卒复用 4 次 |
| 环境 | 正式地图仍用平铺砖墙；验证房有 3 层烘焙图 | 14 个现有区域的连续背景、精确结构层、前景；二楼与下层统一构图 |
| 道具 | 有少量像素占位，21 个交互锚点 | 文书柜、祭坛、公告板、门、梯、装备架、名册、戒指等独立资源；交互状态拆分 |
| 战斗 | 多数反馈由线、圆和文字绘制 | 刀光、命中、弹反、破韧、处决、投射物、魂光、技能反馈 |
| 界面 | Godot 默认控件和文字 | 状态条皮肤、装备与碎片图标、时间轴节点、按钮、提示图标 |

**第一批先做囚徒 + 灰烬士兵 + 牢房/走廊/没收架。** 这一段可同时验证人物比例、角色动作、地面接触、取回装备与环境风格。随后做下水道/通风管、档案/骑士长廊、大厅、责难官房、二楼和典狱长。王城入口与皇宫前厅只按已有占位范围制作，不扩建后续宫殿。

## 2. 统一风格与视角

- 以 `ArtSources/target.png` 为气氛参考：暗黑中世纪、绘画质感、有体积的石材/木材/铁器；可以用 Blender 建模后烘焙。原有“64×96 像素角色”是历史占位规格，新正式美术采用下面的规格。
- 低饱和蓝灰石材、暗棕木材、锈铁，琥珀火把和青蓝符文作局部重点。保留可见中间调，不能把可玩区域压成纯黑。
- 角色严格侧视，默认面向右；背景可表现材质与厚度，实际行走面必须是固定侧视投影。建筑不使用消失点改变平台高度。
- 主角、敌人、武器、道具、背景保持同一绘画风格和光向。先做同框样张；不要批量混合像素人物、照片墙面和卡通特效。
- 环境光采用柔和冷光，主光以画面左上方为基础。角色不烘焙很强的单侧火焰光，避免水平翻转后光向突变。
- 默认利用水平翻转产生左向动作。非对称纹章、单眼、披肩如果必须保留左右身份，则另做左右向动作，这会增加交付量。

## 3. 尺寸总原则：三种尺寸分别看

| 参数 | 已有运行值 / 新制作要求 |
| --- | --- |
| 游戏基准画面 | 1280×720；其他窗口尺寸由游戏缩放 |
| 游戏坐标比例 | 1 游戏单位 = 64 游戏像素；本制作流程约定 1 单位对应 Blender 1 米 |
| **新正式素材制作密度** | **128 源像素/单位，即现有游戏坐标的 2 倍** |
| 新资源接入缩放 | 默认 0.5；源图 256 像素对应游戏 128 像素。还需要修改素材节点的缩放/锚点，不能把大图按现有 1.2 倍直接替换 |
| 主角实际碰撞 | 40×108 游戏像素，脚底是节点原点；源图对照矩形为 80×216 |
| 当前所有敌人碰撞 | 50×108 游戏像素，源图对照矩形 100×216；BOSS 当前也一样 |
| 当前验证房 | 2560×1024、64 像素/单位，尚未改成正式 2 倍密度 |
| 最终格式 | PNG，8 位 RGBA；背景最远层可 RGB。保留图层源文件；颜色按 sRGB 交付 |

这些是**最终制作/导入规格**，不是对图片模型原生输出尺寸的保证。可以先让 Image 2.5 在方便的分辨率生成参考，再对齐、裁切、抠图或通过 Blender 重建并渲染成指定尺寸。不能通过拉伸背景强行对齐地面。

UI 按 1280×720 游戏画面设计，源图也采用 2 倍尺寸；所有文字由 Godot 排版，不让图片模型把中文写进按钮或卷宗。

## 4. 角色：图片交付规格

### 4.1 普通角色与首批全部敌人

| 项目 | 要求 |
| --- | --- |
| 图片生成参考 | 单个角色一张 1024×1024 的透明概念图；这是设计图，不直接当动画帧 |
| 每帧正式画布 | **512×512，透明 PNG** |
| 脚底锚点 | **(256, 448)**，从左上角计；站立时两脚最低接触点在 y=448 |
| 标准人体高度 | **216 源像素**；站立头顶约 y=232。接入后约 108 游戏像素，与现有碰撞匹配 |
| 身体宽度 | 主角肩/躯干约 64～88 源像素；敌人约 76～104；披风、武器可超出身体碰撞 |
| 基础姿态 | 正右侧、全身、头脚完整，站立脚底保持水平；手部握点可辨识 |
| 动作画布 | 同一套动作不改画布与脚底锚点；跳跃/死亡允许姿势离开接触线，但节点原点不随裁切移动 |
| 武器空间 | 出剑幅度较大的动作统一改用 1024×512，脚锚点 (512,448)；整段动作固定规格，不能有一帧突然换画布 |
| 透明边缘 | 真 alpha；不带白/灰底、棋盘格、地面、固定投影、轮廓白边或发光框；边缘允许正常抗锯齿 |
| 源素材 | 分层 PNG/PSD/Krita 文件，至少保留人体、衣物、主手、副手、特效层；或 Blender 模型+动作源文件 |

身体、装备、刀光必须能分开。为了减少穿帮，首批可以交付已经组合装备的完整动作图，但另保留没有武器的基础人体及装备独立图；之后再逐步做换装。不要把 27 件武器都永久画进同一套人体。

如果需要更高大的典狱长，可另设计 2.0～2.2 米版本并同步调整游戏碰撞、受击和动作范围。**首批先用当前 108 像素人体高度，避免凭一张巨型 BOSS 立像改变战斗判定。**

### 4.3 动作清单

建议按 24 fps 制作基本时间采样；最终播放以现有逻辑时长为准，必要时调整单帧时长。以下是交付帧数建议，尚未接入 AnimatedSprite2D。

| 动作 | 帧数建议 | 循环 | 要求 |
| --- | --- | --- | --- |
| idle | 8 | 是 | 呼吸轻微；脚底不滑动 |
| walk | 8 | 是 | 行走左右脚可辨；足部接触周期一致 |
| run / sprint | 10 / 10 | 是 | 分别对应 6 / 9 单位每秒；冲刺姿势与普通跑可区分 |
| jump_start / rise / fall / land | 3 / 2 / 2 / 3 | 上升/下降可保持 | 上升与下降分开；着地压缩不能改变物理脚锚点 |
| light_attack | 13：3 蓄力 + 4 命中 + 6 收招 | 否 | 对应当前 0.11 / 0.15 / 0.25 秒三阶段；刀光另交 |
| heavy_attack | 20：7 + 4 + 9 | 否 | 对应 0.28 / 0.18 / 0.38 秒 |
| shield_bash | 16：4 + 4 + 8 | 否 | 对应 0.18 / 0.16 / 0.35 秒 |
| guard / parry | 持盾 2～4 / 弹反 6 | 持盾可循环 | 盾面保持稳定；弹反起手明显 |
| dodge | 8 | 否 | 躯干前移，脚部/姿势连续；不要把位移画成画布移动 |
| hurt / stagger / exhausted | 3 / 6 / 6 | 力竭保持可循环 | 玩家硬直、敌人破韧、可处决状态应能看懂 |
| drink / death | 8 / 12 | 否 | 原素瓶握持清楚；死亡末帧保持 |
| double_jump / dash / cast / prayer | 4 / 6 / 8 / 8 | 按动作 | 后续能力和职业动作；可以第二批做 |

轻/重攻另外需要空中版本和双手版本；第一批先完成单手直剑与士兵横斩，不一次性生成全部组合。每个敌人至少 idle、walk、各招式 windup/active/recovery、hurt、exhausted、death。精英招式直接使用 `art_manifest.json` 同目录的 `COMBAT_ANIMATION_REQUIREMENTS.md`，以现有攻击时间作为约束。

优先交付逐帧 PNG，命名 `prisoner/light_attack/frame_001.png`。需要图集时：512×512 单格、8 列、边缘各 2 像素透明间隔；一行图集宽 4112 像素，坐标必须附 JSON。更方便的首批格式是无间隔 4 列图集，2048×(512×行数)，使用 Godot 的固定网格切帧。带间隔图集不能按普通 hframes/vframes 平均切分。

图片模型生成的多姿态图仅当作关键姿势参考；完整帧序列还要做身份一致性、手指数、武器长度、脚锚点和时间轴整理。不要将一张“8 姿势海报”直接认作已完成的游戏动画。

## 5. 背景：按真实地图出图

### 5.1 房间与世界坐标

完整数表见 [ROOM_DIMENSIONS.md](ROOM_DIMENSIONS.md)，其中包括 14 个房间的宽度、高度、地面行号和分块数。

- 监狱主区域：X=-85～44，共 129 单位，即 **8256 游戏像素**。正式 2 倍密度的主监狱总构图为 **16512×2880 源像素**，世界高度范围 Y=-5.5～17。
- 这个大画布是布局总图，**不要交付为一张运行时大图**。按房间或最多 16 单位（2048 源像素）分块。
- 每块四边外扩 **64 源像素（0.5 单位）**，便于接缝；交付宽高比核心范围各多 128。例如 16 单位监狱块：核心 2048×2880，交付 **2176×3008**。
- 二楼 X=-42～18、地面 Y=7，与下层在同一个世界空间中重叠。它不是另一个独立横向房间；不可再画一条不同高度的下层地面。
- 王城街道、皇宫前厅、军械库、档案夹层采用核心高度 1792，地面核心行号 1280；交付高度 1920，地面交付行号 1344。
- 监狱所有块的放置使用相同 topY=17、bottomY=-5.5；这为二楼和高台留出空间，空白处允许透明。

**正式图只在定义的核心范围内承担主体内容，外扩用于重复边缘。** 相邻外扩区必须来自同一构图或统一裁切，避免两个独立生成的窗口/门在接缝重复。接入时使用一致的裁切/遮罩规则；否则两个半透明外扩层相叠会变暗。

### 5.2 每块拆成这些图层

| 图层 | 交付与用途 |
| --- | --- |
| `bg_far` | 远景墙、深处建筑、远处雾；最远层可不透明；第一阶段可静止 |
| `bg_architecture` | 墙、柱、拱、固定背景栏杆；其余透明 |
| `terrain` | 按蓝图地面、高台和台阶制作的主体；平台上缘精确对齐；其余透明 |
| `props_static` | 固定柜架/碎石/不可动刑具；最好保留对象独立源层 |
| `fg` | 少量靠镜头的锁链、铁栏、碎石；透明；可覆盖角色，但不挡住必需的交互提示 |
| `light_static` | 可选静态光影层；也可烘进背景。不能拿它代替动态火焰/技能光 |
| `guide` | 地面、碰撞、交互锚点和角色比例参考；制作时叠加，最终图片隐藏 |

同一块所有完整图层使用**相同交付宽高、同一原点、同一镜头**；不要各自自动裁掉透明边。门、可动梯子、火焰、符文、水面和拾取物另交，不画死在这些层里。

相邻房间共享的远墙/远景可以合并制作；不存在的图层不交付整张透明大图。源图保留完整对齐画布，运行打包时可裁切透明空白并记录 offset，按当前房间与邻块加载，减少重复纹理。绘画素材接入时使用局部 Linear 过滤，保留旧像素素材原有过滤；最终过滤/压缩以实际画面验证。

第一批采用静态远景。若后续加入视差，只移动没有地面/交互标记的远景层；terrain 和与碰撞相连的物体不做视差。

### 5.3 不能改变的关键轮廓

- Cell/PrisonCorridor 连续地面：X=-85～-73，Y=0。
- Sewer：X=-73～-57，Y=-1.5；当前是连续可走地面。不要将验证房中央的水坑复制到这里形成新坑。
- Vent：X=-57～-53 的 Y=-0.5；-53～-49 的 Y=0.5；-49～-45 的 Y=1.5；-45～-41 的 Y=2.5。**四段各 4 单位宽，每段高差 1 单位。** 当前采用台阶/平台跳跃，不自行画成景深转弯楼梯。
- 中层与大厅主路：X=-41～44，主要 Y=2.5；门/物件不能堵住已规划的战斗路线。
- 骑士长廊高台：X=-9.5～-6.5，Y=6.2；相对主路高 3.7。
- 大厅高台：X=18～26，Y=6.1；相对主路高 3.6。
- 二楼：X=-42～18，Y=7；单向平台，其美术需表现角色能够由下方跳上去的合理结构。
- 捷径梯：X=-30，连接 Y=2.5 与 7。正式游戏的调查切换逻辑仍按原坐标执行。

蓝图 `layout_guides/*.png` / `.svg` 已按实际数据生成：绿=实体地面，黄=单向高台，蓝=交互锚点，白色 80×216 框=主角碰撞参考。把对应蓝图与 target 图一起提交给图片模型；说明彩线是约束，最终画面不能出现彩线和标签。

角色接触的平地边缘最终误差不超过 **2 源像素（1 游戏像素）**。如果 AI 生成的行走面偏移，按蓝图修图或在 Blender 中重建；不能把游戏碰撞移去迁就一张随机构图。

## 8. 环境材质与 Blender 源文件

### 8.1 图片生成适合做什么

适合：风格样张、角色/武器概念、独立道具、可平铺底色、背景绘画细节、特效关键形态。生成材质建议 **1024×1024 无缝正方形**：石墙、湿石、石地、木板、锈铁、暗铁、布料；每种先 2 个变体。图上不带透视、不含门窗/道具、不带方向性大阴影。

真正的 normal/roughness/metallic 图要由材质制作工具或 Blender 处理。AI 画的蓝紫色图片不能直接当作正确法线图，底色里也不要画死强光和阴影。第一批用底色 + 合理常量粗糙度即可。

### 8.2 人物模型是否必须

**游戏内不要求实时三维角色模型。** 首批可交付二维动画；如果希望稳定地产生完整动作、换武器和一致光影，则推荐用 Blender 人物源模型 + 骨骼动画，再按侧面正交镜头批量烘焙透明序列。最后仍由 Godot 的二维角色使用。

Image 2.5 可以给模型设计参考，但人物图片不等于拓扑、UV、骨骼、蒙皮和动画。需要真正的模型制作步骤。当前 `.blend` 是环境工程，没有人物骨骼与动作；不能从它直接得到角色动画。

### 8.3 Blender 人物源模型交付

- 源文件 `.blend`；需要可交换文件时附带带骨骼 `.glb`。不要求游戏运行时导入人物 GLB。
- X 向右、Z 向上、Y 为景深，脚底原点 (0,0,0)。首批人物高度约 1.6875 米，对应当前 108 游戏像素；正面/侧面比例保持人形。
- 建议普通人物 1～2.5 万三角面、精英 2～4 万，作为离线制作预算而非引擎硬限制；不用为背景烘焙牺牲必要细节。
- 人体/服饰、主手、副手、披风可拆对象；骨架手腕提供 `weapon_r`、`weapon_l` 挂点。骨架、对象、动作名称固定。
- 建议单角色 2048×2048 底色材质图；粗糙度、法线由真实材质/烘焙产生。材质按需要分体，不要求每个小配件一张 4K 图。
- A/T Pose、UV、正常蒙皮；手指能握武器，肩肘膝在动作中不穿帮。动作含本规格列表与敌人技能列表。
- root motion 不驱动游戏位移；动画源动作以原地为主。实际奔跑、闪避和击退由二维控制器控制，避免双重位移。
- 渲染侧视镜头沿 +Y 看向人物，X/Z 对齐画面水平/垂直；正交，无倾斜，固定分辨率与取景。基础 512×512、ortho_scale=4 米；脚底相对画面行号 448 对应镜头中心 Z=1.5 米。
- 宽攻击画布 1024×512 时横向取景 8 米、纵向仍 4 米；Blender 横向正交尺度设置 8，避免人物变大。两种画布源密度均为 128 像素/米。
- 透明背景、柔和固定光，角色不渲染地板投影；接触阴影在 Godot 单独处理。所有帧使用同一色彩管理和输出设置。

### 8.4 环境源模型与渲染

Blender 已安装在 `E:\blen\blender.exe`。制作时可随时用其后台模式读取、校准镜头、恢复贴图和批量渲染。

- 现有模型可复用材质和牢门/砖石/锁链等模块，但不能整体搬入正式地图：验证房宽约 38.6 单位，正式监狱主路宽 129 单位。
- 根据蓝图重排模块，保留 COL、MARK 和 VIS/FG/FX 分组。COL 参考世界 X/Z 轮廓；游戏最终碰撞仍来自二维关卡数据。
- 命名 `BG_*`、`VIS_*`、`FG_*`、`FX_*`、`DOOR_*`、`COL_*`、`MARK_*`；COL 不参加美术渲染；动态门、火焰、符文、水面主体可独立渲染。
- 场景单位 1 米，原点与 `art_manifest.json` 一致。镜头 `(centerX, negativeY, centerZ)`，旋转 `(90°,0,0)`，禁止俯仰让画面地面线和二维碰撞错开。
- 带外扩的 16 米块：画面宽 17 米、高 23.5 米，输出 2176×3008。这是竖幅画面，应使用垂直 sensor fit / 对应 view frame 核验取景；不能把宽 17 米直接作为 AUTO 纵幅相机的正交尺度。横纵像素密度都必须为 128/米。
- 每层用同镜头和构图。渲染后用 MARK 与地面投影核验；原有源文件中的斜坡方盒和景深楼梯不能照搬为二维实体。
- `.blend` 纹理必须打包或附带 `textures/`；不得依赖作者电脑上的绝对路径。源文件保留，不覆盖原提交文件。
- 最终输出 PNG 层与锚点 JSON；游戏只载入生成图层，不依赖运行时 Blender。

同一房间的各层附 JSON：`room_id`、`segment_id`、世界 minX/maxX/topY/bottomY、画布宽高、源密度128、缩放0.5、像素原点/锚点、图层顺序。每套角色动画附动作名、循环标记、每帧持续时间、脚锚点、武器握点、攻击阶段帧索引。

验收顺序：

1. 与当前角色/场景同框看比例和风格；通过后再批量出图。
2. 透明底是真 alpha，边缘没有底色；全身、武器和道具不被裁切。
3. 每帧画布/锚点一致，身份、武器长度、服饰和光向连续。
4. 背景叠蓝图检查全部地面、高台、梯、交互点；不能自行增删游戏路线。
5. 完整背景隐藏 guide 和 UI；门、拾取物、火焰等动态内容在独立层。
6. Godot 接入后测试跑跳、挥刀、开门、拾取和前景遮挡；角色脚底与平台上缘对齐。

本包提供美术生产规格与布局蓝图。主角现已使用 `charactrers.png` 制作六种外观、18组动作，并按512×512画布、脚锚点(256,448)、缩放0.5接入；流程和限制见根目录 `PLAYER_CHARACTER.md`。主流程正式背景与敌人素材仍待制作，独立验证房已有环境烘焙和门状态绑定。

布局 PNG 的 21 个分块尺寸已核对；Blender 5.2.2 的 6 个镜头/投影坐标检查通过。可以通过 `blender.exe --background --factory-startup --python tools/check_art_camera.py` 重验脚底锚点、人体高度、横幅攻击取景和纵幅场景取景。
